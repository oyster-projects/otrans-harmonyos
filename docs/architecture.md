# OTrans 架构决策

## 产品边界

- HarmonyOS 客户端只在用户打开应用或主动点击“重新读取”时读取当前剪贴板，不在后台监听剪贴板。
- 照片和文件由用户主动选择、拖入或通过系统分享入口交给 OTrans。
- fnOS 是数据权威中心，负责设备配对、记录、文件实体、事件流和回收。
- 内网穿透、DDNS、VPN 和反向代理不由 OTrans 实现。客户端只保存一个可访问的服务地址。

## 数据与删除语义

一次上传是一条 `transfer`，可包含多个文本、照片或文件项。文件按 SHA-256 存储，相同内容只保留一份。

用户在任意端删除中转记录后：

1. fnOS 将记录标记为已删除并产生 `transfer.deleted` 事件。
2. 各客户端收到事件后删除 OTrans 自己管理的 Inbox 和缓存副本。
3. fnOS 删除不再被其他未删除记录引用的文件实体。
4. 用户手动“另存为”或复制到 OTrans 管理范围之外的文件不受影响。

## 同步模式

- 自动：客户端按事件游标增量拉取，并发出系统通知。
- 手动：客户端只在用户点击同步时拉取，服务端仍保留其独立游标。
- Windows 上行：监视的 Outbox 文件夹只把“写入已完成”的文件建立为新中转记录，避免上传半成品。

## 协议要点

- 管理员令牌只用来创建 10 分钟有效的一次性配对码。
- 每台设备在配对后获得独立令牌，服务端只保存令牌哈希。
- 文件上传与记录提交分离，只有全部文件齐备后记录才对其他设备可见。
- 公网使用必须在 fnOS 前面配置 HTTPS；不应在明文 HTTP 公网连接上传送设备令牌。

## 实施阶段

1. 文本闭环：配对、打开 App 读取剪贴板、上传、服务端记录。
2. 手机照片/文件、历史记录和全局删除界面。
3. Windows 托盘客户端、Inbox/Outbox、通知与手动/自动同步。
4. 续传、配额、过期策略、设备撤销和发布签名。
